# Рабочее окружение команды

У каждой команды свой сайт, свой git-репозиторий и своя база PostgreSQL.
Ниже — как с ними работать и что нельзя ломать.

## Команды и сайты

| Команда (`team.id`) | Сайт |
| --- | --- |
| `arjunis` | https://team-arjunis.codenotes.ru |
| `deploy-knee` | https://team-deploy-knee.codenotes.ru |
| `poltora-admina` | https://team-poltora-admina.codenotes.ru |
| `soborny-kommit` | https://team-soborny-kommit.codenotes.ru |

Сайт работает по HTTPS, сертификат валидный, порт не указывается.

## Ваш сервис

Приложение — Python 3.11 и FastAPI. Точка входа — `main.py` в корне
репозитория с объектом `app`; при деплое код копируется в `/workspace/src` и
запускается `uvicorn main:app`. Обязательные эндпоинты:

| Метод | Что делать |
| --- | --- |
| `GET /healthz` | вернуть 200. Это проверка живости, её опрашивает платформа |
| `GET /db-check` | проверить подключение к своей БД, вернуть 200, если соединение есть |
| `GET /` | на ваше усмотрение, можно не делать |

Проверить сайт руками:

```bash
curl -i https://team-<id>.codenotes.ru/healthz
curl -i https://team-<id>.codenotes.ru/db-check
```

Если `/healthz` отдаёт не 200 — сервис считается лежащим, даже если остальное
работает.

## Переменные окружения

Уже подставлены в среду — читайте их из кода. Вписывать значения в
репозиторий не нужно, они уже есть.

| Переменная | Что это |
| --- | --- |
| `DB_HOST` | хост вашей БД |
| `DB_PORT` | порт БД |
| `DB_NAME` | имя вашей БД |
| `DB_USER` | ваша роль в БД |
| `DB_PASSWORD` | пароль этой роли |
| `GIT_REVISION` | ревизия, которая сейчас задеплоена |
| `PERSISTENT_DIR` | каталог с диском команды (`/persistent`) |

Пароль БД нигде в коде не храните: он приходит из `DB_PASSWORD`.

## Данные и файлы

- `/persistent` — личный диск команды, 1 GiB. Переживает перезапуск: сюда
  кладите то, что должно сохраниться (файлы, SQLite, выгрузки).
- Остальная файловая система эфемерна: после перезапуска всё, что вне
  `/persistent`, пропадает.
- `/workspace/src` — копия кода из репозитория. Правки здесь не сохраняются:
  меняйте код в git.

## Зависимости

Базовые библиотеки уже есть: `fastapi`, `uvicorn`, `sqlalchemy`, `psycopg`,
`alembic`, `httpx`. `pip` и `venv` в контейнере есть, PyPI доступен.

Свои зависимости добавьте в `requirements.txt` в корне репозитория, с точными
версиями — например, `fastapi==0.115.0`. Установятся при следующем деплое.
Без пинов набор может «поехать» между деплоями — пишите `==`.

## Ресурсы

Один контейнер, одна копия сервиса:

| | CPU | Память |
| --- | --- | --- |
| гарантировано | 0.01 | 10 MiB |
| лимит | 0.2 | 200 MiB |

Превышение памяти ведёт к перезапуску — не держите в памяти большие файлы
и кеши.

В контейнере есть root: можно ставить пакеты (`pip install`; системные —
только если доступны https-репозитории). Root — внутри контейнера, доступа
к хосту он не даёт.

## Git и деплой

- Репозиторий команды: `https://git.codenotes.ru/team-<id>/team-service`,
  ветка `main`. Это отдельный репозиторий, не общий репозиторий проекта.
- Пуш — под своей учётной записью Forgejo: по SSH-ключу из настроек профиля
  либо по HTTPS со своим логином (токен доступа — там же, в профиле).
- Писать в репозиторий своей команды могут все её участники; репозитории
  других команд недоступны.
- Деплой — по заявке: платформа перезапускает сервис на новой ревизии `main`.
  Сам по себе пуш ничего не деплоит.
- Во время деплоя сайт недоступен 10–20 секунд. Работает одна копия сервиса.
- `GIT_REVISION` показывает задеплоенную ревизию — сверяйте с
  `git rev-parse HEAD`.

## Правила

1. Секреты (пароли, токены, ключи) в git не коммитить. Пароль БД — только из
   окружения.
2. Не пытаться получить доступ к данным других команд.
3. Не ломать `/healthz`: он должен отвечать 200 после любых правок.
4. В `main` держать рабочее состояние — деплоят именно его.
5. Не хранить состояние вне `/persistent`: остальное сбрасывается.

## Куда обращаться

Логины и пароли БД — в студенческом портале (там же будут логи сервиса).
Заявки на деплой, статус сервиса и вопросы — платформенной команде курса.
